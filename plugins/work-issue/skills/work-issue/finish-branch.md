**Finish an own branch.** The branch is the one whose `PUSHED` line carries the id of the `PLAN … current` line (`PUSHED <branch> <head sha> <count> <plan id>`). Its commits were made by an earlier run of this skill on the current plan (each carries the `Work-issue-plan` trailer of step 8, all with this plan's id), and the run was aborted before `gh pr create`. Reason it is recognised by the trailer and not by the branch name or the account: `ACCOUNT` is usually the owner's own login, and a branch the owner made by hand must not be finished and merged unattended. One commit without the trailer (a hand-made commit on top) makes `issue-context.py` print `-` as the plan id, and the branch is somebody's started work.

Steps 2, 3, 5 and 6 do not apply: nothing is planned, changed, bumped or committed, and the plan's base commit is not compared. The branch was built on the current plan; a default branch that moved since is handled after the PR exists, by the branch update under "Merging" of the `issue-worker`. What runs:

- Put the branch under the checkout exactly as the second bullet of `resume.md` describes for a PR branch (fetch; `git rev-parse --verify refs/remotes/origin/<branch>` must equal the head of the `PUSHED` line; `git switch --no-overwrite-ignore --track` for a missing local branch, otherwise the `rev-list --count` check and the `--ff-only` fast-forward), with the `PUSHED` head in the place of the `RESUME` head. The difference: none of these stops writes a stop marker, because no PR exists to carry one.
- Record the untracked entries right after the successful switch (and after `git merge --ff-only`), as in the third bullet of `resume.md`: `git -c core.quotePath=false status --porcelain --untracked-files=all > <temporary directory>/status-after-switch.txt`.
- Step 4 installs the dependencies (no reproduction). Check that the branch holds the version bump step 6 would make: `git diff --name-only refs/remotes/origin/<default>...HEAD` has to list the manifest (and lockfile) of the `MANIFEST` line that step 6 bumps. Without it stop and report "own branch without the version bump".
- Step 7 validates the head. A failing validation is not fixed here: stop and report it.
- Green: step 8 without commit and push. Open the PR with `gh pr create --base <default> --head <branch> --title "<type>(<scope>): <what changes>" --body-file <temporary directory>/pr-body.md`, the body as step 8 describes it (`Closes #<n>`, the plan link, **Why**, **What**, **Verification**, **Not verified**). **What** is written from the branch's diff against the default branch (`git diff refs/remotes/origin/<default>...HEAD`) and names the bump commit as the diff shows it; it says that the version scripts' run during the bump was not observed by this run. **Not verified** says that this run did not make the commits.
- Done when the PR is open on the head of the `PUSHED` line for which step 7 held. Report the `PUSHED` line, the PR and the validation result.

A stop in finish mode writes nothing to GitHub: there is no PR for a stop marker, so the next run finds the same branch and stops again until a person acts. Say that in the report. The clean-up is that of resume mode in `resume.md` (the three commands and their conditions: a stop before the switch leaves the checkout unchanged and runs none of them; a refused `git merge --ff-only` after the switch, or a stop after it, gets `git reset --hard`, `git switch` to the branch `WORKTREE` named or `git switch --detach` to the commit kept in step 1, and `git clean -fd` only after the switch succeeded). The commits stay on the remote.
